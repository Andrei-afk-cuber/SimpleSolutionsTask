# SimpleSolutionsTask

Тестовое задание для Simple Solutions: REST API на FastAPI с фоновыми задачами на Celery, хранением данных в PostgreSQL и брокером сообщений Redis. Весь стек поднимается одной командой через Docker Compose.

> Данное приложение состоит из двух частей: клиент (отвечает за периодческий сбор данных с deribit api, а в качестве планировщика используется celery beat) и API (на FastAPI) для взаимодействия с БД и отправкой данных пользователю.

## Технологии

| Компонент | Технология |
|---|---|
| Веб-фреймворк | FastAPI + Uvicorn |
| ORM / модели | SQLModel (поверх SQLAlchemy) |
| База данных | PostgreSQL (драйвер `psycopg2`) |
| Миграции | Alembic |
| Фоновые задачи | Celery (worker + beat) |
| Брокер | Redis |
| Тесты | pytest |
| Запуск | Docker, Docker Compose |

## Архитектура

В `docker-compose.yaml` описано шесть сервисов:

| Сервис | Назначение |
|---|---|
| `database` | PostgreSQL, с healthcheck через `pg_isready` |
| `redis` | Брокер для Celery, с healthcheck через `redis-cli ping` |
| `migrate` | Одноразовый контейнер: выполняет `alembic upgrade head` и завершается |
| `api` | FastAPI-приложение (`uvicorn app.main:app`), порт `8000` |
| `worker` | Celery-воркер (`app.client.celery_app`), выполняет фоновые задачи |
| `beat` | Celery beat, запускает периодические задачи по расписанию |

Порядок старта: `database` → `migrate` → (`api`, `worker`, `beat`). Воркер и beat дополнительно ждут healthy-состояния Redis.

## Быстрый старт (Docker)

### Требования

- Docker 20.10+
- Docker Compose v2 (команда `docker compose`)
- Свободные порты: `8000` (API), `5432` (PostgreSQL), `6379` (Redis) — порты БД и Redis можно изменить в `.env`

### Запуск

1. Клонируйте репозиторий:

   ```bash
   git clone https://github.com/Andrei-afk-cuber/SimpleSolutionsTask.git
   cd SimpleSolutionsTask
   ```

2. (Опционально) проверьте и при необходимости поправьте `.env` — значения по умолчанию подходят для запуска «как есть».

3. Соберите и запустите все сервисы:

   ```bash
   docker compose up --build
   ```

   Для запуска в фоне добавьте флаг `-d`.

4. Дождитесь, пока контейнер `migrate` завершится со статусом `exited (0)` — после этого стартуют `api`, `worker` и `beat`.

5. Проверьте, что API отвечает:

   - Swagger UI: <http://localhost:8000/docs>
   - ReDoc: <http://localhost:8000/redoc>

### Полезные команды

```bash
docker compose ps                      # состояние сервисов
docker compose logs -f api             # логи API
docker compose logs -f worker beat     # логи Celery
docker compose down                    # остановить сервисы
docker compose down -v                 # остановить и удалить данные БД
```

## Конфигурация

Настройки задаются переменными окружения в файле `.env`:

| Переменная | По умолчанию | Описание |
|---|---|---|
| `DB_HOST` | `127.0.0.1` | Хост PostgreSQL (в Docker переопределяется на `database`) |
| `DB_PORT` | `5432` | Порт PostgreSQL |
| `DB_USER` | `postgres` | Пользователь БД |
| `DB_PASSWORD` | `postgres` | Пароль БД |
| `DB_NAME` | `postgres` | Имя БД |
| `REDIS_HOST` | `127.0.0.1` | Хост Redis (в Docker переопределяется на `redis`) |
| `REDIS_PORT` | `6379` | Порт Redis |

> В `docker-compose.yaml` для сервисов `api`, `worker`, `beat` и `migrate` значения `DB_HOST` и `REDIS_HOST` принудительно заменяются на имена сервисов внутри Docker-сети. Поэтому один и тот же `.env` работает и для Docker, и для локального запуска.

> ⚠️ Значения в `.env` предназначены только для разработки и проверки. В production задайте надёжные пароли и не храните секреты в репозитории.

## Локальный запуск без Docker

Нужны Python 3.11+, PostgreSQL и Redis, доступные по адресам из `.env`.

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# применить миграции
alembic upgrade head

# API
uvicorn app.main:app --reload --port 8000

# воркер и планировщик (в отдельных терминалах)
celery -A app.client.celery_app worker --loglevel=info
celery -A app.client.celery_app beat --loglevel=info
```

> На Windows для воркера Celery может понадобиться флаг `--pool=solo`.

Быстро поднять только БД и Redis из Compose:

```bash
docker compose up database redis
```

## Миграции базы данных

Миграции управляются Alembic и лежат в `migrations/`. В Docker они применяются автоматически сервисом `migrate`.

```bash
# применить все миграции
alembic upgrade head

# создать новую миграцию по изменениям моделей
alembic revision --autogenerate -m "описание изменения"

# откатить последнюю миграцию
alembic downgrade -1
```

Интерактивная документация генерируется автоматически и доступна по адресу <http://localhost:8000/docs> (OpenAPI-схема: <http://localhost:8000/openapi.json>).

> | Метод | Путь          | Описание                                                                                                                                                                                                                                         |
> |---|---------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
> | `GET` | `/prices`     | Получение всех цен для указанной валюты (для указания валюты испольщуется query-параметр ticker с возможными значениями btc_usd и eth_usd). Также возможна сортировка по дате, которая указывается по query-параметру date в формате YYYY-mm-dd. |

## Design decisions

### FastAPI как веб-фреймворк

Асинхронный фреймворк с автоматической валидацией запросов через Pydantic и встроенной OpenAPI-документацией. Это сокращает объём «обвязки» и даёт готовую интерактивную документацию API без дополнительных усилий.

### SQLModel + Alembic

SQLModel позволяет описывать модели один раз и использовать их и как таблицы SQLAlchemy, и как Pydantic-схемы, что уменьшает дублирование кода. Схема БД версионируется через Alembic: изменения воспроизводимы, откатываемы и применяются одинаково в любом окружении.

### Celery + Redis для фоновых задач

Долгие и периодические операции вынесены из HTTP-цикла в отдельные процессы, поэтому API остаётся отзывчивым. Redis выбран брокером как самый простой в развёртывании вариант, который покрывает потребности задачи. Воркер и планировщик масштабируются независимо от API.

### Отдельные `worker` и `beat`

Beat запускается отдельным процессом, а не флагом `-B` внутри воркера. Так при масштабировании числа воркеров расписание не дублируется: в системе всегда ровно один планировщик.

### Миграции — отдельный one-shot сервис

Миграции вынесены в сервис `migrate`, который выполняется один раз и завершается. Остальные сервисы ждут его через `condition: service_completed_successfully`. Это исключает гонку, когда несколько контейнеров одновременно пытаются мигрировать схему, и гарантирует, что приложение никогда не стартует на устаревшей БД.

### Healthcheck и порядок запуска

Для PostgreSQL и Redis настроены healthcheck, а зависимости построены через `condition: service_healthy`. Сервисы стартуют только когда зависимости реально готовы принимать соединения, а не просто когда контейнер запущен. Это убирает типичные ошибки подключения при холодном старте.

### Один образ для всех сервисов приложения

`api`, `worker`, `beat` и `migrate` собираются из одного `Dockerfile` и различаются только командой запуска. Код один и тот же, поэтому нет риска рассинхронизации версий между API и воркером, а сборка и кэширование слоёв упрощаются.

### Конфигурация через переменные окружения

Все настройки подключений вынесены в `.env` (подход 12-factor). Значения хостов внутри Docker-сети переопределяются в `docker-compose.yaml`, поэтому один файл подходит и для контейнеров, и для локальной разработки.

### Docker Compose для развёртывания

Один файл описывает весь стек, и проверяющему достаточно команды `docker compose up --build`: не нужно вручную ставить PostgreSQL, Redis и настраивать окружение.
